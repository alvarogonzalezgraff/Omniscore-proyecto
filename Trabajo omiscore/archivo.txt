## 2 Introducción

### 2.1 Presentación del proyecto

Omniscore es una aplicación web integral de apuestas deportivas y estadísticas deportivas que ofrece información detallada sobre múltiples ligas y competiciones deportivas. El proyecto se ha desarrollado como una plataforma completa que combina funcionalidades de gestión de usuarios, visualización de datos deportivos en tiempo real, y un sistema robusto de backend con API RESTful.

La aplicación cubre principalmente fútbol europeo (LaLiga EA Sports, Liga Hypermotion, Premier League, Bundesliga, Serie A), baloncesto (NBA, Euroliga, ACB), y tenis (ATP, WTA, Grand Slams), proporcionando estadísticas detalladas, clasificaciones, resultados y análisis de partidos.

El proyecto implementa una arquitectura moderna basada en FastAPI para el backend, PostgreSQL como base de datos principal, y un frontend dinámico con HTML5, CSS3 y JavaScript vanilla, todo desplegable mediante contenedores Docker para facilitar el despliegue y escalabilidad.

## 3 Metodología y temporalización

### 3.1 Metodología de trabajo

El desarrollo de Omniscore ha seguido una metodología ágil iterativa, con ciclos de desarrollo cortos que permitieron la evolución continua del producto. La metodología implementada incluyó:

- **Desarrollo iterativo**: Sprints de 2 semanas con entregables funcionales
- **Integración continua**: Implementación de Docker para asegurar consistencia entre entornos
- **Versionado con Git**: Control de versiones con ramas feature y main para producción
- **Testing incremental**: Pruebas unitarias y de integración durante cada sprint
- **Documentación continua**: Actualización paralela de documentación técnica

### 6.2 Tablas de Especificación

**CU-01: Registro de Usuario**
- Actor: Usuario No Registrado
- Descripción: Permite a nuevos usuarios crear una cuenta en el sistema
- Precondiciones: Ninguna
- Flujo básico:
  1. Usuario accede a página de registro
  2. Completa formulario con datos requeridos
  3. Sistema valida datos
  4. Sistema crea cuenta de usuario
  5. Usuario redirigido a página principal
- Postcondiciones: Usuario registrado en sistema

**CU-02: Inicio de Sesión**
- Actor: Usuario Registrado
- Descripción: Permite a usuarios existentes acceder al sistema
- Precondiciones: Usuario debe tener cuenta válida
- Flujo básico:
  1. Usuario accede a página de login
  2. Introduce credenciales
  3. Sistema autentica credenciales
  4. Sistema crea sesión
  5. Usuario redirigido a página principal
- Postcondiciones: Usuario autenticado

**CU-03: Consulta de Estadísticas**
- Actor: Usuario Registrado
- Descripción: Permite consultar estadísticas detalladas de ligas y equipos
- Precondiciones: Usuario debe estar autenticado
- Flujo básico:
  1. Usuario selecciona deporte/liga
  2. Sistema muestra opciones de consulta
  3. Usuario selecciona tipo de estadística
  4. Sistema presenta datos con filtros
  5. Usuario puede interactuar con datos
- Postcondiciones: Estadísticas visualizadas

## 7 Diagramas de Secuencia

### 7.1 Diagrama de Secuencia - Autenticación

```
Usuario -> Frontend: Acceder a Login
Frontend -> Usuario: Mostrar formulario Login
Usuario -> Frontend: Introducir credenciales
Frontend -> API: POST /api/auth/login
API -> BaseDatos: Verificar usuario
BaseDatos -> API: Datos usuario
API -> API: Generar token JWT
API -> Frontend: Token + datos usuario
Frontend -> Frontend: Guardar en localStorage
Frontend -> Usuario: Redirigir a inicio
```

### 7.2 Diagrama de Secuencia - Consulta de Partidos

```
Usuario -> Frontend: Seleccionar liga
Frontend -> API: GET /api/matches?league_id=X
API -> BaseDatos: Consultar partidos liga X
BaseDatos -> API: Datos partidos
API -> API: Procesar y formatear
API -> Frontend: JSON con partidos
Frontend -> Frontend: Renderizar tabla partidos
Frontend -> Usuario: Mostrar resultados
```

### 7.3 Diagrama de Secuencia - Actualización Automática

```
Scheduler -> Scraper: Iniciar scraping
Scraper -> WebExterna: Request datos
WebExterna -> Scraper: Response HTML
Scraper -> Scraper: Parsear datos
Scraper -> BaseDatos: Insertar/Actualizar datos
BaseDatos -> Scraper: Confirmación
Scraper -> Scheduler: Tarea completada
```

El proyecto Omniscore representa una solución completa y moderna para la gestión y visualización de datos deportivos, cumpliendo con éxito los objetivos planteados inicialmente. 1. **Arquitectura Sólida**: Se ha construido una arquitectura moderna basada en microservicios, con FastAPI como backend, PostgreSQL como base de datos, y un frontend responsivo. La implementación de Docker asegura la portabilidad y escalabilidad del sistema.

2. **Funcionalidad Completa**: La aplicación ofrece un conjunto completo de características incluyendo autenticación de usuarios, visualización de estadísticas en tiempo real, scraping automático de datos, y una API RESTful bien documentada.

3. **Experiencia de Usuario**: La interfaz es intuitiva y moderna, con un diseño oscuro atractivo, navegación fluida, y responsive design que funciona perfectamente en dispositivos móviles y desktop.

4. **Datos en Tiempo Real**: El sistema de scraping implementado permite mantener los datos actualizados automáticamente, proporcionando información fresca y relevante a los usuarios.

5. **Escalabilidad**: La arquitectura basada en contenedores y el diseño modular permiten escalar el sistema horizontalmente para manejar crecientes volúmenes de usuarios y datos.

- **Rendimiento**: La API responde en menos de 2 segundos para consultas típicas

- **Calidad de Código**: Código limpio, bien documentado, y con cobertura de tests
- **Flexibilidad**: Sistema modular que permite añadir fácilmente nuevos deportes y ligas
